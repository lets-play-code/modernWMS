# ModernWMS UI / UX 设计风格规范

> 本文总结当前系统多数页面已经稳定形成的视觉与交互模式，目标不是做一次全量重设计，而是让新增页面继续“看起来像 ModernWMS、用起来也像 ModernWMS”。
>
> 这份规范主要覆盖常规后台管理页；大屏可视化与 3D VWMS 属于特殊场景，单独作为例外说明。

## 1. 设计目标

### 1.1 整体定位

当前 ModernWMS 的主界面风格可以概括为：

> **桌面优先、轻品牌化、浅色后台、表格为中心、流程状态清晰、交互尽量稳定可预期。**

它不是营销型官网，也不是移动端优先产品，而是典型的企业后台管理系统。

### 1.2 优先级排序

新增页面设计时，优先级建议如下：

1. **业务效率优先**：先保证录入、筛选、查看、确认操作顺畅
2. **一致性优先**：优先像现有页面，而不是追求单页创意
3. **信息密度优先于装饰性**：列表、状态、操作按钮比插画和视觉特效更重要
4. **可维护性优先**：优先复用现有组件和布局节奏

## 2. 页面布局体系

### 2.1 登录页

登录页采用明显的左右分栏：
- 左侧：品牌插画 / 视觉承载
- 右侧：登录表单
- 右上：语言切换
- 底部：版权与备案信息

设计含义：
- 登录页允许比后台页面更“展示型”
- 但仍保持轻量，不使用复杂动画或多层引导

新增登录相关页面应继续保持这种“左视觉、右表单”的结构，而不是改成纯居中卡片式 SaaS 登录页。

### 2.2 后台主壳层

后台主壳层由三部分组成：
- 左侧导航栏 `HomeSideBar`
- 顶部面包屑与工具栏 `HomeHeader`
- 主内容区 `RouterView`

关键布局参数：
- 侧边栏展开宽度约 `300px`
- 折叠宽度约 `100px`
- 顶栏高度约 `60px`
- 主内容区左右保留明显留白（当前 `home.vue` 为 `5%`）

这说明当前系统不是“铺满整屏的极限密度布局”，而是保留了一定呼吸感的企业后台风格。

### 2.3 常规管理页

多数业务页面共享下面的层级：

```text
页面容器
└── v-card
    └── v-card-text
        ├── 操作区 operateArea
        │   ├── 左侧按钮组 BtnGroup
        │   └── 右侧搜索区 / SearchGroup
        ├── 主表格 vxe-table
        └── 底部分页 custom-pager
```

这套骨架是当前“多数页面”的默认样式，应优先复用。

### 2.4 流程 / 阶段页

入库、出库、仓内作业等流程型页面通常会在卡片上方增加：
- `v-tabs`
- 图标 + 文本的堆叠式 tab
- `v-window` 承载分阶段内容

适用场景：
- 到货通知 → 到货 → 卸货 → 分拣 → 上架
- 发货 → 拣货 → 打包 → 称重 → 出库 → 签收

当业务本身就是阶段推进时，应优先使用 tab 表达流程，而不是拆成多个风格完全不同的页面。

## 3. 视觉风格令牌

### 3.1 主色与辅助色

当前视觉主色明确偏向紫色系。

| 用途 | 色值 | 典型场景 |
| --- | --- | --- |
| 品牌主色 | `#9C27B0` | 首页标题、重点文字、分页激活色 |
| 激活渐变 | `#AF85FC → #9155FD` | 侧边栏当前菜单背景 |
| 浅紫底色 | `#ECE7F6` / `#E8E2FB` | 轻强调背景、头像底色 |
| 危险色 | `#BA2828` | 删除等高风险操作 |
| 中性灰 | `#444` / `#666` / `#999` / `#B9B8BC` | 正文、次级文字、辅助信息 |
| 悬停灰 | `#EDEEF3` / `#E4E5EA` | 菜单和工具图标 hover |
| 背景浅灰 | `#FAFAFA` | 登录页右侧表单区 |

规则：
- 紫色用于品牌识别与选中状态
- 红色只用于危险动作，不要泛化为普通强调色
- 大面积背景优先白色或浅灰，不做重色块铺底

### 3.2 圆角与阴影

当前界面并不是完全扁平化，而是保留了轻量卡片感：
- 顶栏与卡片常见 `10px` 左右圆角
- 侧边栏激活项是右侧圆头胶囊形
- 顶部工具图标与头像是圆形容器
- 阴影普遍较轻，用于分层，不用于制造强烈浮起感

新增页面应保持“轻阴影 + 中等圆角”的企业后台风格，不要突然改成完全无圆角或超大圆角。

### 3.3 图标系统

当前主图标系统基于 Material Design Icons：
- 菜单图标
- 顶部工具图标
- tab 图标
- 操作列图标

规则：
- 菜单与 tab 使用语义稳定的线性图标
- 行内操作图标保持小尺寸、单色、带 tooltip
- 不要混用另一套风格割裂的图标库

## 4. 常规后台页面设计规范

### 4.1 信息结构顺序

在标准管理页里，信息层级应保持：
1. 当前所在位置（面包屑）
2. 当前页面可执行操作
3. 当前筛选条件
4. 当前数据表格
5. 当前分页状态
6. 需要时再出现弹窗或详情层

也就是说，新增页面不要把筛选、操作、表格、批量动作打乱成全新布局。

### 4.2 搜索区布局

当前搜索区常见节奏：
- 使用 `v-row + v-col`
- 单行通常按 `4 + 4 + 4` 三等分组织
- 输入框普遍使用 `variant="solo"`
- `clearable + hide-details + density="comfortable"` 是常见组合

如果一个列表只需要 1 个搜索项，也常通过前置空列维持整体对齐节奏，而不是让控件随意散落。

### 4.3 表格区布局

表格是当前系统最核心的视觉主体。

规则：
- 内容区域优先留给表格，不要让大标题、插图、装饰块挤占表格空间
- 表格列默认居中对齐，强调“台账感”
- 操作列放右侧，危险动作使用红色图标
- 空状态用统一文本提示，不做花哨空页面

如果页面是以列表为主，就应让用户一眼先看到“可筛选、可操作、可翻页的数据表”。

### 4.4 分页与底部区

分页区统一放在表格底部，采用：
- 页码
- 每页条数选择
- 总记录数

不要把分页器拆到卡片外、悬浮到顶部，或改成另一种完全不同的交互形式。

## 5. 组件级交互规范

### 5.1 顶部按钮组

当前顶部操作按钮主要通过：
- `BtnGroup`
- `tooltip-btn`

呈现方式特点：
- 小尺寸图标按钮
- 依赖 tooltip 解释动作语义
- 适合高频工具操作

规则：
- 常用动作优先继续使用图标按钮
- 高风险动作在列表行内或弹窗中仍可用红色图标提示
- 不要在普通管理页突然引入一整排高饱和实体主按钮

### 5.2 表单弹窗

当前新增/编辑弹窗的典型样式：
- `v-dialog`
- 顶部白色 `v-toolbar`
- 表单项使用 `variant="outlined"`
- 底部按钮右对齐

交互规则：
- 打开弹窗即聚焦于表单任务
- 校验失败给出即时提示
- 提交成功后关闭弹窗并刷新列表

### 5.3 反馈机制

当前统一反馈方式：
- `hookComponent.$message()`：轻提示
- `hookComponent.$dialog()`：确认/二次确认

规则：
- 普通成功、失败、警告信息使用 message
- 删除、确认等破坏性动作使用 dialog 二次确认
- 不要为单页临时接入另一套 toast / modal 机制

### 5.4 权限状态表达

当前按钮权限并不总是“隐藏”，很多地方是：
- 无权限或不可执行时直接 `disabled`
- 仍保留按钮位置，避免布局跳动

因此新增高频操作时，优先延续“禁用但可见”的表达方式，方便用户理解该动作存在，只是当前不可用。

## 6. 导航与流程体验规范

### 6.1 左侧导航

侧边栏当前的显著特征：
- 分组式导航
- 激活菜单使用紫色渐变胶囊高亮
- hover 使用浅灰底
- 支持折叠

规则：
- 新增菜单应延续当前分组结构，不要无节制增加一级导航
- 激活态保持明显，但不要引入第二种主激活颜色

### 6.2 顶部面包屑

当前顶部面包屑较简洁：
- 主要用于说明当前页面位置
- 不承担复杂跳转与多级操作

因此新增页面无需在顶栏堆叠过多辅助按钮，顶栏应继续保持“定位 + 全局工具”的轻量风格。

### 6.3 流程页 tabs

流程型页面的 tab 不是装饰，而是主要业务状态导航。

规则：
- tab 名称必须直接反映业务阶段
- 图标应帮助用户快速识别流程位置
- 同一业务流程内的 tab 风格保持一致

## 7. 响应式与适配边界

当前系统是**桌面优先**，不是移动端优先。

明显特征：
- 多数页面依赖表格宽度
- 常见 `min-width: 760px`
- 高度通过 `computedCardHeight()` / `computedTableHeight()` 适配视口
- 侧边栏提供折叠，但不是移动抽屉式导航

因此新增页面设计时应默认服务于：
- 桌面浏览器
- 宽屏后台使用场景
- 高频键鼠操作

不要按移动端卡片流布局去改造常规后台页面。

## 8. 特殊场景例外说明

### 8.1 首页

首页不是表格页，而是品牌页：
- 大标题 `ModernWMS`
- 轻插画 / Lottie 动效
- 大面积留白

它的作用是建立品牌识别和欢迎感，属于后台系统中的视觉例外。

### 8.2 统计分析页

统计页在常规表格骨架之上增加：
- 表格 / 图表切换
- 图表作为同一数据集的另一种展示方式

这说明统计页仍应继承后台主风格，只是在内容层增加图表，不应完全脱离管理台的视觉体系。

### 8.3 大屏页

`largeScreen` 属于特殊展示模式：
- 深色背景
- DataV 风格边框
- 全屏展示
- 强视觉装饰

它不应反向成为普通后台页面的设计模板。

### 8.4 VWMS 3D 页面

`VWms` 是沉浸式 3D / Unity 交互页：
- iframe 承载 3D 场景
- 侧边浮层卡片展示详情
- 支持货架二维视图叠层

它是功能特例，不代表一般后台 CRUD 页的设计方向。

## 9. 新增页面 UI / UX 检查清单

- [ ] 是否优先复用了现有后台壳层与页面骨架
- [ ] 是否优先使用紫色主品牌色和既有中性色体系
- [ ] 是否复用了 `BtnGroup`、`tooltip-btn`、`custom-pager`、`SearchGroup` 等组件
- [ ] 是否保持“操作区 → 搜索区 → 表格 → 分页”的阅读顺序
- [ ] 是否使用统一的 message / dialog 反馈方式
- [ ] 是否把危险操作明确标红并加确认
- [ ] 是否所有用户可见文案都接入 i18n
- [ ] 是否确认该页面属于常规后台页，而不是误用了大屏 / 3D 特例样式

---

## 10. 当前应避免的新设计写法

1. 在普通后台页引入全新主题色体系
2. 使用过强的渐变、阴影、玻璃拟态等装饰压过业务信息
3. 把表格页改造成大量卡片瀑布流，损失台账可读性
4. 在不同页面混用多种按钮语义和反馈机制
5. 只追求视觉新颖，破坏现有操作顺序与用户习惯
6. 把大屏 / 3D 页面风格反向套到普通 CRUD 页面

---

## 11. 一句话版本

> ModernWMS 的 UI / UX 主风格是：**桌面优先、浅色后台、紫色品牌强调、表格为中心、流程状态清晰、交互稳定且可复用**；大屏和 3D 页面属于少量特例，不应成为普通业务页的默认模板。
